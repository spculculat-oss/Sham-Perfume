1. أمر `build:pages` يبني المصدر الحالي إلى `docs` بمسار `/Sham-Perfume/`، وينشئ `404.html` متوافقًا و`.nojekyll`.

6. الطلبات غير الناجحة أو التي تعيد HTML بدل JSON تظهر كأخطاء. فشل تحديث الأخبار في المتصفح أو الخادم لا يضيف خبرًا مصنوعًا ولا يُظهر نجاحًا كاذبًا.
7. الخادم يدعم `PORT` المقدم من الاستضافة، ويعيد JSON 404 لمسارات API غير الموجودة، ويعرض حالة مفاتيح الخدمات الحقيقية في `/api/models`.

## Sham Core — مساعد الخدمات ولوحة الإدارة

هيكل ذكاء اصطناعي خاص بشام، معمول من الصفر، وبيستقبل الزوار في كل الخدمات: الأدوات، المتجر، العطور المخصصة، الجملة B2B، الاستشارات، والدعم. **بيشتغل من غير أي مفتاح**: التوجيه والاسترجاع والأدوات والذاكرة كلها داخلية. ولو حبيت تضيف نموذج لغوي، تقدر تستخدم نموذج مفتوح مستضاف ذاتياً (Ollama أو vLLM) أو أي مزود خارجي، والتبديل بينهم تلقائي لو واحد فشل. الشرح الكامل ودراسة منصات ChatGPT وClaude وGemini وDeepSeek وManus موجودين في [`SHAM_CORE.md`](SHAM_CORE.md).

- الزائر: زر «مساعد شام للخدمات» في الركن المقابل لشاهين. منه بيعمل الطلبات بسلة أسعارها محسوبة على الخادم، ويتتبع طلبه برقم الطلب مع الهاتف أو البريد، ويتحول لموظف ويستلم رده في نفس المكان.
- الإدارة: `/#admin` باستخدام `SHAM_ADMIN_TOKEN`. فيها الطلبات، والمحادثات والرد عليها، والمنتجات، وقاعدة المعرفة، وإضافة خدمات تجارية جديدة من غير كود، وترتيب المحركات، ومختبر بمسار التنفيذ.
- التخزين: `SHAM_STORE=file` على Node/VPS، و`SHAM_STORE=firestore` على Vercel/Firebase. راجع `.env.example`.
- المرحلة الثانية (تحليل سلوكي لأدوات المحادثة): ردود بتتكتب مباشرة (streaming) مع خطوات التنفيذ، واقتراحات للمتابعة، وتقييم 👍/👎 بيتحول لفجوات معرفة الإدارة بتسدها، وذاكرة الزائر مع «ماذا تعرف عني؟» و«امسح بياناتي»، وإدخال وقراءة بالصوت، ومساعد إداري بيخطط وبيكتب تقارير، وإشعارات Webhook موقّعة. التفاصيل في [`AI_TOOLS_REVERSE_ENGINEERING.md`](AI_TOOLS_REVERSE_ENGINEERING.md).

## التشغيل المحلي

المطلوب: Node.js 22.x بإصدار 22.12 أو أحدث داخل هذا الإصدار الرئيسي (راجع `.nvmrc`)، وBun **1.4.3** المثبت في `package.json`. ملف `bun.lock` هو مرجع التبعيات؛ إصدارات Bun القديمة قد لا تفهم نسخة ملف القفل.

```bash
npx --yes bun@1.4.3 install --frozen-lockfile
cp .env.example .env
npm run dev
```

افتح `http://localhost:3000`. ضع مفاتيح الخدمات في `.env` محليًا أو متغيرات بيئة الخادم فقط. الحاسبات والمكتبات لا تحتاج مفاتيح؛ تحديث الأخبار يحتاج `GEMINI_API_KEY`. بيانات الحسابات والتركيبات والمحادثات المحفوظة موجودة في متصفح المستخدم، وليست قاعدة بيانات مركزية على GitHub.

**لا تضع مفاتيح الذكاء الاصطناعي في `VITE_*` ولا في ملفات `docs` أو GitHub؛ هذه الملفات عامة.**

## النشر على GitHub Pages

### الخيار الموصى به: البناء الآلي من المصدر

بعد دمج فرع الإصلاح في `main`:

1. افتح **Settings → Pages → Build and deployment → Source** واختر **GitHub Actions** بدل **Deploy from a branch**.
2. افتح **Actions → Build, test and deploy Pages** ثم أعد تشغيل العملية على `main` أو شغّلها عبر **Run workflow**.
3. ستبني العملية المصدر، وتتحقق من الملفات، ثم تنشر artifact المجرّب. لا تنشر فروع العمل أو طلبات الدمج للموقع العام.

لم يتم تغيير إعداد Pages العام أو نشر/دمج فرع العمل خلال المراجعة. الـworkflow يعطي رسالة واضحة إذا لم يتغير إعداد Pages إلى GitHub Actions؛ لا يسمح بنشرين متنافسين من إعدادات الفرع والعمل الآلي.

المسار الافتراضي هو `/<اسم المستودع>/`. للمجال المخصص أو مستودع موقع المستخدم، اضبط Repository Variable باسم `PAGES_BASE_PATH` إلى `/`. وللبناء المحلي المقابل:

```bash
PAGES_BASE_PATH=/ npm run build:pages
PAGES_BASE_PATH=/ npm run check:pages
```

### إبقاء الإعداد القديم: main/docs

إذا اخترت عدم الانتقال إلى GitHub Actions، أعد البناء يدويًا مع كل تغيير، ثم ارفع **المصدر وملفات `docs` معًا** عبر فرع العمل وطلب دمج إلى `main`:

```bash
npm run build:pages
npm run check:pages
git status
```

ملفات `docs` موجودة في Git للحفاظ على التوافق مع النشر القديم. `dist` و`node_modules` لا تُرفع.

> GitHub Pages يستضيف الواجهة الثابتة فقط ولا يشغّل `server.ts`. عشان الشات بوتات تشتغل عليه، الـ workflow بيبني النسخة الثابتة بـ `VITE_API_BASE_URL`، فالواجهة بتكلّم خادم Vercel مباشرة. القيمة جاية من متغير المستودع `PAGES_API_BASE_URL`، والافتراضي `https://sham-perfume-49bf.vercel.app`.
> الخادم بيسمح بالطلبات دي بس للدومينات المكتوبة في `SHAM_CORS_ORIGINS`، والافتراضي `https://spculculat-oss.github.io`.
> مفاتيح الذكاء الاصطناعي بتفضل على Vercel وعمرها ما توصل للمتصفح.

## نشر الواجهة وAPI معًا على Vercel

نجاح نشر Vite إلى `dist` وحده لا يشغّل شاهين. هذا المشروع يستخدم **Build Output API v3** لبناء الواجهة ودالة Node.js في نشر واحد، ولا يحتاج اختيار Express preset أو وضع Vite داخل الدالة.

- `server/app.ts`: تطبيق Express والمسارات فقط، بلا `listen` وبلا Vite.
- `server.ts`: تشغيل محلي/استضافة Node.js تقليدية؛ ليس مدخل دالة Vercel.
- `server/vercel-entry.cts`: مدخل دالة Vercel؛ يُجمع بواسطة esbuild إلى حزمة CJS مستقلة.
- `scripts/build-vercel.mjs`: يضع الواجهة في `.vercel/output/static` والدالة في `.vercel/output/functions/api.func`، مع توجيه كل `/api/...` إلى الدالة **قبل** fallback الواجهة. الملفات المولدة لا تُرفع إلى Git.
- `tsconfig.json` يفحص السيرفر بأنواع Node، و`tsconfig.app.json` يفحص الواجهة بأنواع `vite/client`، لتجنب خلط أنواع Vite بتجميع السيرفر.

### خطوات النشر للمشروع الموجود

1. ادمج طلب الإصلاح في `main` أولًا. لا تحذف مشروع Vercel أو تنشئ مشروعًا جديدًا.
2. افتح مشروع **`sham-perfume-49bf`**، وهو المشروع المرتبط بالرابط `https://sham-perfume-49bf.vercel.app`، وليس المشروع الآخر `sham-perfume`.
3. في **Settings → Build and Deployment**: اجعل **Framework Preset = Other**، و**Root Directory = ./**، و**Node.js Version = 22.x**. لا تستخدم preset Vite أو Express. إعدادات الأوامر تأتي من `vercel.json`؛ ألغِ أي overrides قديمة خصوصًا Output Directory = dist. عند الحاجة لإدخال الأوامر يدويًا:
   - Install Command: `npx --yes bun@1.4.3 install --frozen-lockfile`
   - Build Command: `npm run build:vercel`
   - Output Directory: لا تحدد `dist` أو `docs`؛ اتركه افتراضيًا/بلا override لأن النتيجة هي `.vercel/output`.
4. في **Settings → Environment Variables** أضف `GEMINI_API_KEY` بمفتاح جديد صالح، واختر **Production**؛ اختر **Preview** فقط إن أردت اختبار نشر الفرع أيضًا. لا ترسل المفتاح في المحادثة، ولا تسمِّه `VITE_GEMINI_API_KEY`. مفاتيح بقية المزودين اختيارية؛ شاهين والأخبار بيشتغلوا بأي محرك مهيأ. بعد النشر افتح `/#admin` ← «الخبير شاهين» ← «اختبار الاتصال بالمحركات» للتأكد إن المفتاح صالح فعلاً. إلغاء مفتاح سبق كشفه واستبداله يتم في حساب المزود.
5. من **Deployments** انشر أحدث commit من `main` بعد الدمج. إعادة نشر deployment قديم تعيد الكود القديم، حتى لو حفظت إعدادات جديدة. عند إعادة النشر اختر **Redeploy** بدون استخدام build cache إذا ظهر هذا الاختيار.

### التحقق بعد النشر

- افتح `/api/health`: المتوقع JSON `{"service":"sham-perfume","status":"ok"}` وحالة HTTP 200. هذا يؤكد عمل الدالة فقط.
- افتح `/api/models`: المتوقع JSON بقائمة المحركات. `hasApiKey: true` يعني وجود إعداد المفتاح، **ولا يثبت صحة المفتاح أو نجاح طلب الذكاء الاصطناعي**.
- جرّب إرسال رسالة قصيرة في شاهين. نجاح `/api/chat` عبر POST مع رد من المزود هو اختبار المحادثة الفعلي؛ فتحه في شريط العنوان يرسل GET وليس اختبارًا صحيحًا.
- بدون مفاتيح، `/api/chat` و`/api/news` يعيدان 503 واضحًا بدل ردود/أخبار مصطنعة. ظهور صفحة Vercel `404 NOT_FOUND` على `/api/models` يعني أن دالة هذا الإصلاح لم تُنشر، وليس مجرد مفتاح غير صالح.

التحقق المحلي:

```bash
npm run lint
npm test
npm run build:vercel
npm run test:vercel
```

اختبارات Vercel تشغّل **حزمة الدالة المولدة خارج المشروع، دون node_modules أو .env** وتفحص GET/POST والأخطاء وإعدادات التوجيه. ليست محاكاة كاملة للبنية السحابية ولا اختبارًا لمفتاح حقيقي. GitHub Actions ينفذها مع اختبارات Pages. ذاكرة الأخبار داخل الدالة مؤقتة وقد تُمسح عند cold start أو تختلف بين النسخ؛ ليست قاعدة بيانات دائمة.

**Vercel Hobby مجاني للاستخدام الشخصي غير التجاري فقط**؛ لا تفترض أن متجرًا/استخدامًا تجاريًا مسموح على الخطة. تكلفة وحدود APIs منفصلة عن الاستضافة المجانية.

## ملاحظات Git المهمة

- `modified` في `git status` يعني تغيرًا محليًا غير مسجل في commit؛ لا يكفي وحده لتحديد ما إذا كانت commits سابقة قد رُفعت.
- `Skipped` في Actions يعني خطوة أو مهمة لم تُنفّذ، غالبًا بسبب شرط؛ لا يعني أن Git تجاهل ملفات عند الرفع.
- افحص الفرع الذي تنشر منه الاستضافة فعلًا. لا يلزم العمل مباشرة على `main`: يُفضّل الإصلاح في فرع العمل ثم طلب دمج، وتظل نسخة الموقع كما هي حتى الدمج والنشر.
- أوامر Git منفصلة، وليست أمرًا واحدًا متصلًا:

```bash
git add <files>
git commit -m "Describe the change"
git push origin <your-working-branch>
```

## الخبير شاهين — الإعدادات والسلوك

**مكان الإعدادات (واحد للموقعين):** موقع GitHub Pages وموقع Vercel `sham-perfume-49bf` بيكلّموا نفس الخادم، فأي إعداد لشاهين بيتطبّق على الاتنين مع بعض.

1. **الأساس الدائم:** `server/config/shaheen.ts` (`SHAHEEN_SITE_SETTINGS`): المحركات المسموحة وترتيب «تلقائي»، واسم النموذج لكل محرك، ودرجة الإبداع، وأقصى طول للرد، وتعليمات إضافية، وتفعيل شاهين، والسماح للزائر باختيار محرك. بيتنشر مع الكود.
2. **التعديل من اللوحة:** `/#admin` ← تبويب **«الخبير شاهين»**. التعديل بيشتغل فوراً، وفيه زر «اختبار الاتصال بالمحركات» بيبعت طلب صغير حقيقي لكل محرك ويقول مين شغال وليه لأ. التعديل بيتحفظ بس لو مختلف عن الملف، و«رجوع لإعدادات الملف» بيلغيه.
   - على Vercel من غير `SHAM_STORE=firestore` التخزين مؤقت، والتعديل ممكن يضيع عند cold start (اللوحة بتنبّه). عشان يفضل دائم: فعّل Firestore، أو انسخ «الإعداد الدائم» من اللوحة للملف في (1).
3. **المفاتيح:** في متغيرات الخادم فقط (`GEMINI_API_KEY`، `DEEPSEEK_API_KEY`، `OPENAI_API_KEY`، `ANTHROPIC_API_KEY`، `OPENROUTER_API_KEY`، أو `SHAM_LLM_BASE_URL` لنموذج مفتوح). مفيش مفتاح بيوصل للمتصفح، والمحرك من غير مفتاح بيختفي من واجهة الزوار.

**السلوك:**
- النافذة العائمة وصفحة «خبير المعمل» بيستخدموا سجل واحد وحالة إرسال واحدة. مسح السجل بيلغي الطلب الجاري.
- **تلقائي** بيجرّب المحركات بالترتيب ويتخطى غير المهيأ أو اللي فشل. المهلة 28 ثانية للمحاولة و50 ثانية إجمالاً، والرد بيتنسب للمحرك اللي ردّ فعلاً. اختيار محرك معيّن مش بيتبدّل سراً بمحرك تاني. لو الإدارة قفلت «السماح للزائر باختيار محرك»، كل الطلبات بتمشي تلقائي.
- الردود بتتعرض Markdown (عناوين، ونقاط، وجداول نِسب). كتلة `sham-formula` بتتحوّل لبطاقة «تحويل للحاسبات» بدل JSON خام. الرسائل الطويلة في السياق بتتقصّ وتفضل الوصفة الأخيرة محفوظة، فمش بيتمسح سجل المحادثة.
- **صور وفيديوهات وجداول للتوضيح:** شاهين بيعرض المقارنات والنِّسب في جداول. ولما الصورة أو الفيديو يفيدوا فعلاً (شكل مادة خام، نبات، أداة، طريقة تقطير أو نقع) أو يطلبهم الزائر، بيضيف في آخر الرد كتلة مخفية `sham-media` فيها **مواضيع بحث بس**، من غير روابط، لأن النماذج بتألّف روابط. الموقع بيدوّر عليها عن طريق `GET /api/media?type=image|video|place&q=` (حد 40 طلب في الدقيقة لكل زائر، ونتيجة كل موضوع بتتخزن يوم):
  - **الصور** من Wikimedia Commons وبتظهر باسم المصوّر والترخيص ورابط المصدر. مش محتاجة مفتاح، وبتتفلتر بالنوع والحجم وكلمات غير لائقة.
  - **الخريطة:** لو السؤال فيه أماكن، زي منشأ مادة خام أو مزارع الورد والعود أو مدن ومتاحف وأسواق العطور، شاهين بيكتب لحد 5 أماكن (`places`). الخادم بيجيب إحداثياتها من OpenStreetMap عن طريق Nominatim، ولو مش متاح بيستخدم Photon، بطلب واحد في الثانية والنتيجة بتتخزن أسبوع. وبتظهر خريطة تفاعلية (Leaflet بيتحمّل بس لما يكون فيه أماكن) عليها علامات مرقّمة، وتحتها أسماء الأماكن، والضغط على أي اسم بيروح للمكان على الخريطة. المكان اللي مش معروف بيظهر كرابط بحث في OpenStreetMap. مش محتاجة مفتاح.
  - **الفيديو** من YouTube Data API v3 مع `safeSearch=strict`، وبيشتغل بالضغط من غير كوكيز (`youtube-nocookie`). المفتاح `YOUTUBE_API_KEY`، ولو مش موجود بيستخدم `GEMINI_API_KEY` بشرط إن YouTube Data API v3 متفعّلة في نفس مشروع Google Cloud. لو مفيش مفتاح شغال بيظهر زر «شاهد على YouTube» بنتيجة البحث.
- الأخطاء بتظهر كفقاعة خطأ واضحة فيها زر «إعادة المحاولة»، ومش بتدخل في سياق النموذج.
- حد السؤال 4000 حرف، والسياق 24 رسالة/16000 حرف. معدل الرسائل `SHAM_SHAHEEN_RATE_PER_MIN` (الافتراضي 10 لكل زائر في الدقيقة) بيرجّع 429، والزائر بيتعرّف بمعرّف مجهول من المتصفح (`X-Sham-Visitor`) مش بالـ IP بس، علشان مستخدمين شبكة الموبايل الواحدة ما يتحجبوش مع بعض (التفاصيل تحت).
- **أخبار العطور:** التحديث بيستخدم أول محرك شاهين متاح (مش Gemini بس). المقالات عليها تنبيه إنها تحريرية مولّدة بالذكاء الاصطناعي. التحديث اليدوي بيرجّع نسخة مخزنة لمدة 10 دقائق، وأقصاه 3 مرات في الساعة لكل IP.
- لا تُستخرج وصفة من مجرد كلمات مثل «زيت» أو «كحول». النقل للحاسبة بيحتاج كتلة `sham-formula` صالحة ومجموع نوتات 100%. المقترح التجريبي مش شهادة IFRA.

**حدود التحقق:** اختبارات تكامل حقيقية لخادم HTTP واختبارات محلية باستجابات مزودي خدمات محاكاة؛ يلزم اختبار مفاتيحك الفعلية على استضافة Node.js. لا توجد مفاتيح خدمة مُضافة إلى المشروع، وGitHub Pages وحده لا يشغّل المحادثة.

## السعة والزوار المتزامنون

شاهين مصمم يستقبل أكتر من 1000 زائر في نفس اللحظة. الطبقة دي في `server/core/capacity.ts`:

1. **ذاكرة إجابات** لأول سؤال في المحادثة (الأسئلة الجاهزة وأسئلة زي «الفرق بين EDP وEDT»): السؤال بيتطبّع (تشكيل، همزات، علامات، حروف كبيرة/صغيرة) و100 زائر بيسألوا نفس السؤال في نفس اللحظة = **نداء واحد** للمزوّد. أسئلة المتابعة (اللي فيها سياق) ما بتتخزنش أبدًا. أي تغيير في الإعدادات من لوحة الإدارة بيوصل فورًا.
2. **بوابة المزوّدين**: حد أقصى للنداءات المتزامنة، ولما المزوّد يرد 429 (الحصة خلصت) البوابة بتوقف النداءات عليه للمدة اللي طلبها، وبتتعلم سرعته (AIMD) بدل ما تكرر الطلبات المرفوضة. الزائر بيستنى في الطابور لحد `SHAM_QUEUE_WAIT_SECONDS` وبعدين يا إما ياخد الإجابة، يا إما رد صادق `503 SHAHEEN_BUSY` مع `Retry-After`.
3. **المتصفح** بيعيد المحاولة لوحده 3 مرات حسب `Retry-After` ويعرض «شاهين مشغول حاليًا، سؤالك في الدور…» بدل رسالة خطأ.
4. **حدود عادلة**: الحد لكل زائر (معرّف مجهول في `localStorage`)، وسقف أعلى لكل IP، فمئات الزوار ورا IP واحد (شبكات الموبايل في مصر) ما يتحجبوش.
5. قائمة موديلات Gemini بتتخزن 10 دقايق بدل ما تتطلب مع كل سؤال، و`vercel.json` فيه `"fluid": true` (Fluid compute: نسخة واحدة من الدالة بتخدم طلبات كتير في نفس الوقت).

| المتغير | الافتراضي | المعنى |
|---|---|---|
| `SHAM_ANSWER_CACHE_MINUTES` | 360 | مدة حفظ إجابة أول سؤال (0 = إيقاف) |
| `SHAM_ANSWER_CACHE_ENTRIES` | 2000 | أقصى عدد إجابات محفوظة |
| `SHAM_PROVIDER_MAX_CONCURRENT` | 300 | أقصى نداءات متزامنة للمزوّدين (حتى 900؛ Vercel بيسمح بـ 1024 اتصال للنسخة) |
| `SHAM_QUEUE_WAIT_SECONDS` | 20 | أقصى انتظار في الطابور قبل `SHAHEEN_BUSY` |
| `SHAM_SHAHEEN_RATE_PER_MIN` | 10 | رسائل لكل زائر في الدقيقة |
| `SHAM_SHAHEEN_RATE_PER_IP_MIN` | 300 | سقف الرسائل لكل IP في الدقيقة |
| `SHAM_GEMINI_RPM`، `SHAM_DEEPSEEK_RPM`، `SHAM_OPENAI_RPM`، `SHAM_CLAUDE_RPM`، `SHAM_SELF_HOSTED_RPM`، `SHAM_OPENROUTER_RPM` | يتعلّم لوحده | الحصة المعروفة لكل مزوّد في الدقيقة (مثلًا من صفحة الحدود في AI Studio) |

**الحد الحقيقي هو حصة المزوّد مش الخادم:** حصة Gemini بتتحسب **لكل مشروع مش لكل مفتاح**، والخطة المجانية بتسمح بعدد قليل من الطلبات في الدقيقة، يعني الأسئلة **المختلفة** محدودة بالحصة دي مهما كان الخادم قوي. علشان 1000 سؤال مختلف في نفس الوقت لازم تفعيل الفوترة على مشروع Google (Tier 1) و/أو إضافة مفاتيح مزوّدين تانيين (DeepSeek/OpenAI/Claude/OpenRouter) — البوابة بتوزع الطلبات تلقائيًا على أي مزوّد متاح.

اختبار الحمل (بيشغّل الراوتر الحقيقي مع مزوّد وهمي، من غير أي نداء خارجي):

```bash
VISITORS=1000 SPREAD_S=5 PROVIDER_RPM=2000 node --import tsx scripts/load-test.mts   # حصة مدفوعة
PROVIDER_RPM=15 node --import tsx scripts/load-test.mts                              # حصة مجانية (~3 دقايق)
NAT_IPS=20 node --import tsx scripts/load-test.mts                                   # زوار ورا 20 IP بس
```

| 1000 زائر خلال 5 ثواني | قبل | بعد |
|---|---|---|
| حصة مدفوعة | 100% — 1000 نداء — وسيط 2.4ث | 100% — 412 نداء — وسيط 1.3ث |
| زوار ورا 20 IP | 20% | 100% |
| 1000 سؤال مختلف في نفس اللحظة | — | 100% — أقصى 10ث |
| حصة مجانية (15 طلب/دقيقة) | 6% — 4895 نداء للمزوّد | 83.5% — 715 نداء، والباقي `SHAHEEN_BUSY` صادق |

## طبيب شاهين — الصيانة التلقائية كل 10 دقايق

«طبيب شاهين» (`scripts/doctor/`) وكيل ذكاء اصطناعي صغير بيراجع الخبير شاهين كل 10 دقايق ويصلّح المشاكل لوحده من غير تدخل بشري. بيشتغل على أجهزة GitHub Actions (`.github/workflows/shaheen-doctor.yml`) **مش على خادم الموقع**، وكل فحص حوالي 8 طلبات خفيفة (والسؤال التجريبي بيرجع من ذاكرة الإجابات)، فالزوار مش بيحسوا بيه.

**بيفحص:** الـ API، هل الموقع على آخر نسخة من main (ولو لأ: حد النشر في Vercel؟ بناء فاشل؟)، أوضاع شاهين، سؤال تجريبي (رد فاضي؟ اسم مزوّد ظاهر؟ حصة؟)، ربط GitHub Pages بالـ API، موقع Pages، عدّادات الخادم الحقيقية (نسبة الأخطاء وزمن الرد وحالة المزوّدين — `GET /api/admin/maintenance`)، فحص وبناء main، والصور.

**بيصلّح لوحده:**

| المشكلة | العلاج |
|---|---|
| أسئلة الزوار بتفشل / الأخطاء عالية | تصفير حالة المزوّدين وقائمة الموديلات على الخادم (`POST /api/admin/maintenance`) + إعادة فحص ومزامنة المفاتيح |
| Vercel رافض النشر (الحد اليومي) | يستنى لحد ما الحد يتصفّر وبعدين يعيد النشر (بـ `VERCEL_TOKEN`) أو يعمل كومِت فاضي ينشر آخر نسخة |
| بناء Vercel فشل | يجرب البناء بنفسه: لو نجح يعيد النشر، لو فشل يصلّح الكود |
| فحص main أحمر، اسم مزوّد في الرد، CORS بايظ | **إصلاح كود بالذكاء الاصطناعي** |
| GitHub Pages واقع | يعيد تشغيل البناء والنشر |

**إصلاح الكود:** بيقرا سجل الخطأ والملفات المتعلقة، والنموذج (نفس محركات ومفاتيح شاهين) بيقترح تعديل، وبيتطبق **بس لو عدّى كل الفحوص** (`lint`، كل الاختبارات، بناء Vercel واختباره، فحص EdgeOne) — لو فشل بيبعت الخطأ للنموذج تاني (لحد 3 محاولات) ولو ما نجحش بيرجّع الملفات زي ما كانت. بعد النجاح بيعمل PR ويدمجه (أو push مباشر لو GitHub مش سامح للـ Actions تعمل PR)، ويشغّل بناء Pages، ويراقب الموقع بعد النشر: لو ظهرت مشاكل جديدة مرتين ورا بعض **بيرجّع التغيير تلقائيًا**.

**حدود الأمان (هي اللي بتخليه يشتغل لوحده بأمان):** ما بيتصرفش في مشكلة غير لما تتكرر فحصين (20 دقيقة) إلا لو بناء main أحمر؛ كل علاج له فترة تهدئة؛ أقصى 3 إصلاحات كود في اليوم وإصلاح واحد تحت المراقبة في نفس الوقت؛ ما يقدرش يعدّل كوده هو ولا الـ workflows ولا الأسرار ولا الاعتماديات ولا الاختبارات الموجودة (يقدر يضيف اختبارات جديدة)؛ أقصى 8 ملفات و400 سطر في الإصلاح الواحد.

**السجل:** issue مفتوحة بعنوان «🩺 طبيب شاهين — سجل الصيانة التلقائية» (label `shaheen-doctor`): الجسم لوحة حالة بتتحدث كل فحص، والتعليقات بس لما يحصل حاجة (علاج، إصلاح، رجوع، مشكلة جديدة، رجوع للسلامة). نفس التقرير في لوحة الإدارة ← تبويب «طبيب شاهين»، ومعاه عدّادات الخادم وأزرار العلاج اليدوي.

**الأسرار (Settings → Secrets and variables → Actions):**

| السر | بيدّي الطبيب إيه |
|---|---|
| `GEMINI_API_KEY` (أو أي مفتاح ذكاء اصطناعي تاني موجود) | إصلاح الكود |
| `SHAM_ADMIN_TOKEN` (نفس قيمته في Vercel) | عدّادات الخادم وعلاج الخادم مباشرة |
| `VERCEL_TOKEN` | إعادة النشر على Vercel فورًا |

تشغيل يدوي: Actions ← «Shaheen Doctor» ← Run workflow (`live` يصلّح، `dry` يراجع بس). محليًا للمراجعة بس: `DOCTOR_MODE=dry node --import tsx scripts/doctor/run.mts`.
