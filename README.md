### الإصلاحات

1. أمر `build:pages` يبني المصدر الحالي إلى `docs` بمسار `/Sham-Perfume/`، وينشئ `404.html` متوافقًا و`.nojekyll`.
2. Workflow يفحص TypeScript والاختبارات ويبني المصدر بدل الاعتماد على ملفات قديمة. فروع `arena/**` وطلبات الدمج تُفحص فقط؛ النشر مسموح لـ `main` فقط.
3. بيانات الأخبار المضمّنة المحدثة وترجماتها تتقدم على النسخ القديمة المحفوظة في المتصفح. تُزال سجلات التحديث المحلي التي كانت تُنشأ عند فشل الطلبات، وتُرفض البيانات غير الصالحة وتكرار المعرّفات.
4. صور الأخبار تستخدم أصول البناء الحالي، لا مسارات `/src` أو ملفات hashed من بناء قديم.
5. نسخة Pages توضح أن المحادثة وتحديث الأخبار يحتاجان خادمًا، وتعطّل هذه الطلبات بدل إظهار وعود مضللة بالمحاولة المتكررة.
6. الطلبات غير الناجحة أو التي تعيد HTML بدل JSON تظهر كأخطاء. فشل تحديث الأخبار في المتصفح أو الخادم لا يضيف خبرًا مصنوعًا ولا يُظهر نجاحًا كاذبًا.
7. الخادم يدعم `PORT` المقدم من الاستضافة، ويعيد JSON 404 لمسارات API غير الموجودة، ويعرض حالة مفاتيح الخدمات الحقيقية في `/api/models`.

## التشغيل المحلي

المطلوب: Node.js 22.12 أو أحدث (راجع `.nvmrc`)، وBun **1.4.3** المثبت في `package.json`. ملف `bun.lock` هو مرجع التبعيات؛ إصدارات Bun القديمة قد لا تفهم نسخة ملف القفل.

```bash
npx --yes bun@1.4.3 install --frozen-lockfile
cp .env.example .env
npm run dev
```

افتح `http://localhost:3000`. ضع مفاتيح الخدمات في `.env` محليًا أو متغيرات بيئة الخادم فقط. الحاسبات والمكتبات لا تحتاج مفاتيح؛ تحديث الأخبار يحتاج `GEMINI_API_KEY`. بيانات الحسابات والتركيبات والمحادثات المحفوظة موجودة في متصفح المستخدم، وليست قاعدة بيانات مركزية على GitHub.

**لا تضع مفاتيح الذكاء الاصطناعي في `VITE_*` ولا في ملفات `docs` أو GitHub؛ هذه الملفات عامة.**


الاختبارات تشمل أخطاء الشبكة وHTTP، نسخة Pages بلا API، صلاحية cache وترجماته وصوره، وحالة خدمات الخادم بدون مفاتيح. يُستخدم خادم اختبار مؤقت على منفذ حر، ولا تتصل الاختبارات بمزودي الذكاء الاصطناعي.

يبقى تحذير حجم حزمة JavaScript الكبيرة تحذير أداء، وليس خطأ بناء أو نشر.

## النشر على GitHub Pages

### الخيار الموصى به: البناء الآلي من المصدر

بعد دمج فرع الإصلاح في `main`:

1. افتح **Settings → Pages → Build and deployment → Source** واختر **GitHub Actions** بدل **Deploy from a branch**.
2. افتح **Actions → Build, test and deploy Pages** ثم أعد تشغيل العملية على `main` أو شغّلها عبر **Run workflow**.
3. ستبني العملية المصدر، وتتحقق من الملفات، ثم تنشر artifact المجرّب. لا تنشر فروع العمل أو طلبات الدمج للموقع العام.

لم يتم تغيير إعداد Pages العام أو نشر/دمج فرع العمل خلال المراجعة. الـworkflow يعطي رسالة واضحة إذا لم يتغير إعداد Pages إلى GitHub Actions؛ لا يسمح بنشرين متنافسين من إعدادات الفرع والعمل الآلي.

المسار الافتراضي هو `/<اسم المستودع>/`. للمجال المخصص أو مستودع موقع المستخدم، اضبط Repository Variable باسم `PAGES_BASE_PATH` إلى `/`. وللبناء المحلي المقابل:

```bash
PAGES_BASE_PATH=/ npm run build:pages
PAGES_BASE_PATH=/ npm run check:pages
```

### إبقاء الإعداد القديم: main/docs

إذا اخترت عدم الانتقال إلى GitHub Actions، أعد البناء يدويًا مع كل تغيير، ثم ارفع **المصدر وملفات `docs` معًا** عبر فرع العمل وطلب دمج إلى `main`:

```bash
npm run build:pages
npm run check:pages
git status
```

ملفات `docs` موجودة في Git للحفاظ على التوافق مع النشر القديم. `dist` و`node_modules` لا تُرفع.

> GitHub Pages يستضيف الواجهة الثابتة فقط؛ نجاح نشره لا يعني أن `server.ts` أو `/api/chat` أو `/api/news` تعمل عليه.

## نشر التطبيق الكامل بخادم Node.js

على استضافة تدعم Node.js:

```bash
npx --yes bun@1.4.3 install --frozen-lockfile
npm run build
NODE_ENV=production npm start
```

احتفظ بتبعيات `tsx` وقت التشغيل لأن أمر `start` يشغّل `server.ts` مباشرة. اضبط مفاتيح الخدمات في بيئة الخادم. يقرأ الخادم `PORT` ويستمع على `0.0.0.0`، ويقدم `dist` وAPI من نفس الأصل؛ لا يحتاج المتصفح URL منفصلًا أو `localhost` للوصول إلى API.

## ملاحظات Git المهمة

- `modified` في `git status` يعني تغيرًا محليًا غير مسجل في commit؛ لا يكفي وحده لتحديد ما إذا كانت commits سابقة قد رُفعت.
- `Skipped` في Actions يعني خطوة أو مهمة لم تُنفّذ، غالبًا بسبب شرط؛ لا يعني أن Git تجاهل ملفات عند الرفع.
- افحص الفرع الذي تنشر منه الاستضافة فعلًا. لا يلزم العمل مباشرة على `main`: يُفضّل الإصلاح في فرع العمل ثم طلب دمج، وتظل نسخة الموقع كما هي حتى الدمج والنشر.
- أوامر Git منفصلة، وليست أمرًا واحدًا متصلًا:

```bash
git add <files>
git commit -m "Describe the change"
git push origin <your-working-branch>
```

## إصلاحات شاهين (فرع العمل الحالي)

- المحادثة العائمة والمعمل يستخدمان سجلًا وحالة إرسال واحدة؛ لا يتم تكرار الطلبات عند الإرسال من الواجهتين، ومسح السجل يلغي الطلب الجاري ويتجاهل الردود المتأخرة. أحداث الاستشارة من الحاسبات تقرأ اللغة والسياق الحاليين.
- وضع **تلقائي** يجرب مزودًا مهيأً ثم ينتقل لغيره عند الفشل ضمن مهلة إجمالية 30 ثانية (12 ثانية للمحاولة). لا يدّعي دمج أربعة آراء أو ينسب ردًا جاهزًا لمحرك لم يُستدعَ. الاختيار الصريح لمحرك لا يُستبدل سرًا بمحرك آخر.
- `/api/models` يعرض إعداد المفاتيح فقط، وليس ضمان توفر الخدمة أو صحة المفتاح. تظهر حالة الإعداد في الواجهة، وتعطّل أزرار المزود غير المهيأ. عند غياب المفاتيح يرجع `/api/chat` خطأ `503` واضحًا، لا ردًا محليًا مدّعى أنه ذكاء اصطناعي.
- مفاتيح الخدمات لا تُرسل للمتصفح. يمكن تغيير موديلات الحساب بمتغيرات الخادم `GEMINI_MODEL` و`DEEPSEEK_MODEL` و`OPENAI_MODEL` و`ANTHROPIC_MODEL`؛ أمثلة القيم في `.env.example` وليست ضمانًا أن كل حساب يملك الوصول إليها.
- حد السؤال 4000 حرف، والسياق 24 رسالة/16000 حرف؛ اللغة المختارة تنتقل إلى المزود. أخطاء JSON والمدخلات غير الصالحة ومهلة الخدمة ترجع أكواد JSON مناسبة. الترحيب وأخطاء الاتصال لا تدخل سياق النموذج.
- سجل المتصفح محدود بـ200 رسالة وتاريخ انتهاء ثابت 30 يومًا. السجلات التالفة أو المنتهية تُرفض دون تعطيل المحادثة، وتعمل الواجهة في الذاكرة إذا مُنع التخزين.
- لا تُستخرج وصفة من مجرد كلمات مثل «زيت» أو «كحول» أو نسبة أمان طبية. النقل للحاسبة يحتاج كتلة `sham-formula` مكتملة القيم وصالحة، بمكونات صريحة ومجموع نوتات 100%. لا تُخمن المكونات أو النسب الناقصة. المقترح التجريبي ليس شهادة IFRA أو موافقة للاستخدام الجلدي.
- تعليمات شاهين توضّح أنه مساعد رقمي، ولا يختلق خبرة بشرية أو شهادات أو جرعات علاجية. هذا توجيه للنموذج، وليس بديلًا عن مراجعة خبير مؤهل وسلامة المكونات.

**حدود التحقق:** اختبارات تكامل حقيقية لخادم HTTP واختبارات محلية باستجابات مزودي خدمات محاكاة؛ يلزم اختبار مفاتيحك الفعلية على استضافة Node.js. لا توجد مفاتيح خدمة مُضافة إلى المشروع، وGitHub Pages وحده لا يشغّل المحادثة.
