# فحص دقة حاسبة شام

الفحص بيفرّق بين خطأ في الحساب، وخطأ في إدخال العملية أو عرض الناتج. الأمثلة اللي اتصلحت متغطية باختبارات تتعاد تلقائيًا، من غير أي خدمة أونلاين للحساب. الحاسبة بتفتح على «حساب عادي» للعمليات الأربعة بالترتيب اللي بتضغط بيه. الجدول التالي يخص الحساب العلمي إلا لو اتذكر غير كده.

| الحالة اللي اتراجعت | النتيجة بعد التصحيح |
| --- | --- |
| ترتيب التربيع والمضروب والنسبة | `2²! = 24` و`2²% = 0.04`؛ علامة `%` معناها القسمة على ١٠٠. |
| زر الأس العلمي والكتابة بعد `EXE` | `1 ÷ 2 [×10ˣ] 3` يُحسب `1 ÷ 2000 = 0.0005`. كتابة `*4` بعد تنفيذ `1+2` تكمل من `Ans` وتطلع `12`. |
| `٧٧−١٥÷١٠٠` في العادي والعلمي | في العادي: `٧٧−١٥ = ٦٢` ناتج مرحلي، ثم `٦٢÷١٠٠ = ٠٫٦٢`. في العلمي: القسمة أولًا والناتج `٧٦٫٨٥`؛ العرض الدقيق والمختلط بيكتبوا القيمة العشرية جنب الكسر لما تكون منتهية وقصيرة. |
| فقدان أرقام أثناء الحساب | `sum(1e16,1,-1e16) = 1`؛ و`1 mod 0.1 = 0`. الرقم `9007199254740993` يفضل زي ما هو في العرض الدقيق والنسخ، وطرْح `9007199254740992` منه داخل جدول الخلايا يطلع `1`. |
| الزوايا والتكامل | `tan(90)` في وضع الدرجات غير معرّف. تكامل `cos(360*32*x)` من ٠ إلى ١ في نفس الوضع قريب من الصفر، مش قريب من ١. |
| المعادلات والمتباينات | `(x-0.234)^2+1e-16` مش له جذر حقيقي، حتى لو القيمة قريبة جدًا من الصفر. الأقواس المفتوحة والمقفولة للمتباينات بتفرق بين الجذر المتكرر والجذرين القريبين وعدم وجود حل. |
| الإحصاء | احتمال اختبار t ثنائي الطرف عند `t=12` و`df=179` حوالي `1.00952×10⁻²⁴`، مش صفر. والاحتمال الطبيعي في الفترة `[-1e-18,1e-18]` حوالي `7.97885×10⁻¹⁹`. |
| النسب والمالية | في خانة الفايدة (%)، `٥` و`٥٪` نفس القيمة. تكلفة ثابتة `3`، سعر `0.30` وتكلفة متغيرة `0.20` نقطة تعادلها `30` وحدة، مش `31`. القسط في جدول السداد ما بيتحولش لقسط أخير كبير بسبب التقريب. |

اتراجع كمان حساب المركّبات والمصفوفات والمتجهات، الثوابت وتحويل الوحدات، الرسم والمتتابعات، الإحصاء والاحتمالات، والفرق بين تغيير وحدة الزاوية وترك نتيجة قديمة معروضة. حالات الإدخال والعرض اتجرّبت في الحاسبة نفسها بالكيبورد وبالأزرار، وكمان باللمس بالعربي على شاشة ٣٢٠ بكسل. شرح «شاهين» الأونلاين بيتختبر بردود محاكاة؛ مش مرجع للمقارنات الحسابية.

## إعادة الاختبار

```sh
npm run lint
npm test
# شغّل الموقع أولًا. اختياري: حدّد مسار Chromium و/أو عنوان السيرفر.
node scripts/check-engineering-calculator.mjs
```

ملف `tests/engineeringAccuracy.test.ts` بيحفظ حالات الخطأ والحدود، وبيولّد متعددة حدود بجذور معروفة للتحقق من الجذور والمتباينات. فيه كمان مقارنة مستقلة اختيارية: **٣٧٣٠ حالة في ٢٥ مجموعة**، ببذرة ثابتة. القيم المرجعية من الكسور والعشري عالي الدقة في بايثون، وNumPy وSciPy وmpmath؛ التحقق العددي بيسمح بفروق التقريب المحددة لكل مجموعة. الأدوات دي للاختبار بس، مش تبع تشغيل الموقع:

```sh
python3 -m venv /tmp/sham-calculator-reference
/tmp/sham-calculator-reference/bin/pip install 'numpy==2.4.6' 'scipy==1.15.3' 'mpmath==1.3.0'
/tmp/sham-calculator-reference/bin/python scripts/generate-calculator-reference.py > /tmp/sham-calculator-reference.json
node --import tsx scripts/check-calculator-reference.mts /tmp/sham-calculator-reference.json
```

## حدود الدقة

- الأعداد النسبية، ومضاعفات π والجذر التربيعي البسيط، ممكن تتعرض بصيغة دقيقة داخل حدود التمثيل. باقي العمليات تستخدم أعداد تقريبية؛ عرض `FIX` أو `SCI` أو `ENG` بيغيّر شكل الناتج المعروض، مش القيمة اللي بتستخدمها `Ans`. الأعداد الكبيرة جدًا أو الصغيرة جدًا ممكن تخرج عن النطاق المدعوم.
- التفاضل والتكامل وتحليل الرسم والحل بنقطة بداية نتائج عددية، مش برهان على وجود كل الجذور أو خلوّ الفترة من القطوع. الحل العددي ممكن يرفض نقطة ما قدرش يتحقق منها؛ لمعادلة كثيرة حدود استخدم وضع المعادلات أو الجبر. للجذر التكعيبي الحقيقي لعدد سالب استخدم `cbrt(-8)` أو `root(-8,3)`.
- ترتيب الضرب الضمني محفوظ في الحساب العلمي، مثل `6÷2(1+2) = 1`. لو المقصود `(6÷2)×(1+2)` اكتبه بالأقواس. النتائج اللي اتراجعت مش ضمان لكل صيغة ولا ادّعاء بمحاكاة جهاز بعينه.
