# مجتمع شام — أساس منصة اجتماعية بهوية العطور

## الاتجاه
تجربة اجتماعية مألوفة: موجز في المنتصف، اختصارات، علاقات بين الأعضاء، تفاعل ومحادثات. الهوية والنصوص ملك شام، وليس نسخة من علامة فيسبوك أو أصوله. لا يمكن الادعاء بمطابقة خوارزمياته أو بنيته الداخلية.

## الموجود في الكود (ليس تأكيدًا لتفعيله في الإنتاج)
- حسابات وملفات شخصية، أصدقاء، حظر وإبلاغ.
- موجز، صور، تعليقات وتفاعلات، قصص ومشاركة تركيبات.
- محادثات ونافذة مراسلة، إشعارات وبريد.
- مجلس نقاش، متاجر وبوابة تجار.
- واجهة تعتمد على API وقاعدة بيانات حقيقية؛ لا أعضاء وهميين ولا نجاح محلي مصطنع عند انقطاع الخدمة.

## تطوير هذه الدفعة
- دليل «كل الأقسام» على `#community/menu` يصل للأقسام الحالية من الموبايل والكمبيوتر، بما فيها السوق والبحث عن الأعضاء.
- هوية شام بالألوان الدافئة، وصف واضح للأقسام وتذكير بالخصوصية والإبلاغ.
- فصل مؤشر الصفحة الخام عن ترتيب/تصفية البطاقات حتى لا تتكرر صفحات الأكثر تفاعلاً أو يتوقف قسم التركيبات عند صفحة بلا تركيبات.
- منع استجابة موجز قديمة من الكتابة فوق اختيار أحدث، ومنع ضغطات التحميل المتزامنة.
- إعادة المحاولة عند فشل التحميل، وإتاحة المزيد حتى لو لم تطابق الصفحة الحالية فلتر التركيبات.
- ترتيب الأكثر تفاعلاً يخص المنشورات المحمّلة فقط، والتسمية توضح ذلك؛ ليس خوارزمية توصية شاملة.
- منع نتائج بحث متأخرة من استبدال بحث أحدث.

## مراحل لاحقة تحتاج تنفيذ واختبار مستقل
1. **جاهزية التشغيل:** مراجعة تفعيل قاعدة البيانات والمفاتيح عبر إعدادات الإدارة؛ اختبار التسجيل واستعادة الحساب والمراسلة بين حسابين حقيقيين، والنسخ الاحتياطي والاستعادة.
2. **اكتمال المجتمع:** مجموعات بعضوية وصلاحيات مديرين، صفحات متابعة ومركز بحث موحد. هذه ليست ميزات جديدة مكتملة بهذه الدفعة.
3. **الوسائط:** تخزين مستقل للصور والفيديو، حدود أحجام، فحص ملفات، تحويل فيديو، وسياسة حذف واحتفاظ قبل إضافة ريلز أو بث مباشر.
4. **السلامة:** مراجعة صلاحيات كل مورد، تحديد المعدلات، طابور بلاغات واضح، أدوات إشراف، تصدير وحذف بيانات الأعضاء.
5. **التوسع:** فهارس وقياس أحمال، ترقيم صفحات بمؤشر مركب (الوقت والمعرّف)، ترتيب وتصفية على الخادم، وتحديثات لحظية مدروسة بدل زيادة الاستطلاع بلا حدود.

## أدوات العمل
React وTypeScript وواجهات API وقاعدة البيانات الحالية تكفي لهذه المرحلة. اختبارات Node وفحص TypeScript وبناء Vite للتحقق. لا اشتراكات جديدة، ولا مفاتيح داخل الملفات، ولا وكيل ذاتي مستمر تم تشغيله. أي خدمة خارجية أو تكاليف تشغيل جديدة تستلزم موافقة صاحب الموقع.

## التحقق اليدوي عند تفعيل الخدمة
- افتح المجتمع وسجل الدخول ثم «كل الأقسام»؛ جرّب الروابط والبحث في شاشة ضيقة واتجاهي العربية والإنجليزية.
- بدّل فلاتر الموجز بسرعة مع اتصال بطيء؛ ينبغي ألا تظهر نتائج الاختيار القديم.
- حمّل صفحات التركيبات حتى لو الصفحة الأولى بلا تركيبات، وتأكد من عدم تكرار البطاقات.
- اقطع الاتصال، جرّب إعادة المحاولة، وتأكد من عدم عرض نجاح وهمي.

## الدفعة الثانية — المنشورات المحفوظة
- حفظ وإلغاء حفظ من قائمة المنشور، مع منع الضغط المتزامن ورسالة نجاح بعد رد الخادم فقط.
- فلتر «المحفوظات» ورابط مباشر `#community/saved` من دليل الأقسام.
- التخزين في جدول `saved_posts`، خاص بكل عضو ومشترك بين أجهزته؛ لا إشعار للناشر ولا كشف لقائمة من حفظوا المنشور.
- المحفوظات مرتبة حسب تاريخ نشر المنشور، وليست تاريخ حفظه.
- الحظر وتغيير خصوصية المنشور وإخفاؤه أو حذفه يمنع ظهوره حتى لو كان محفوظًا. إلغاء الحفظ يظل مسموحًا للعضو صاحب الحفظ دون كشف محتوى المنشور.
- ترقية المخطط إلى الإصدار 8 تضيف جدولًا دون حذف البيانات الحالية، وفق آلية الترحيل الموجودة. يلزم نشر الخادم والواجهة؛ لم يتم تشغيل ترحيل على قاعدة الإنتاج من هذه الجلسة.
- اختبارات قاعدة البيانات تغطي خصوصية المحفوظات، تكرار الطلبات، والحظر وتغيير الصلاحيات؛ واختبارات HTTP تغطي اشتراط تسجيل الدخول ومسار الحفظ والإلغاء.
