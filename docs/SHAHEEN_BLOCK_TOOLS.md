# مصنع أدوات شاهين بالبلوكات

## ما يعمل الآن

في **مساحة شاهين → بلوكات** يوجد مفسّر محلي لتعريف أدوات JSON. يركّب شاهين خمسة أمثلة من طلب واضح بالعربية أو الإنجليزية: الخصم، التركيز، تنظيف النص، تربيع قائمة وجمعها، وشرط النجاح. طلب غير معروف أو يخلط أمثلة متعددة لا ينتج أداة بديلة بصمت.

يمكن تركيب أدوات أخرى بتعديل التعريف، أو بزر **صمّم أداة جديدة بالوصف (يحتاج اتصال)** عبر محرك مساحة شاهين المهيأ وبحصته إن كان متاحاً. يرسل الزر الوصف فقط، لا مدخلات التشغيل ولا الملفات. ينتج المحرك تعريف JSON لا كوداً تنفيذياً؛ يرفض الخادم والواجهة التعريف إن خالف المخطط أو فشل تشغيله بالقيم الافتراضية. هذا فحص بنيوي وتجربة افتراضية فقط وليس إثباتاً مستقلاً أن الأداة تحقق كل متطلبات الطلب أو كل المدخلات. إلغاء التصميم أو تبديل المثال يمنع وصول رد متأخر ليكتب فوق الاختيار الجديد. غياب الخدمة يظهر خطأ صريحاً ولا يتحول إلى نجاح أو أداة مختلفة. لا يحتاج تركيب الأمثلة المحلية أو تشغيل التعريفات خدمة خارجية. التعريف يتكوّن من:

- `version: 1` و`title`.
- `inputs`: معرّف لاتيني فريد، `label`، و`type` من `number | text | boolean | list`، و`default` مطابق.
- `nodes`: معرّف فريد و`expr`، بالترتيب. المراجع لبلوك سابق فقط؛ لا دورات ولا مراجع مستقبلية.
- `outputs`: أسماء البلوكات التي نريد عرض قيمها.

بعد التحرير اضغط **افحص وطبّق التعريف**، غيّر المدخلات واضغط **شغّل الأداة**. التشغيل لا يعتمد على خدمة ذكاء اصطناعي أو مفتاح. شات شاهين يتعرف على طلب صريح مثل «ابني بالبلوكات حاسبة خصم». شات مساحة العمل يعرض زر **افتح في البلوكات** للتعريف الذي يجتاز الفحص. أي JSON مقترح يُعامل كبيانات غير موثوقة ويُفحص من جديد عند التشغيل.

الحفظ والاسترجاع على **الجهاز الحالي** فقط، وليس حساب المستخدم. لا تحفظ مدخلات التشغيل ضمن التعريف المحفوظ؛ القيم الافتراضية التي تكتبها داخل التعريف نفسه تدخل طبعاً في ملفه. الاستيراد والتصدير بصيغة JSON. فشل التخزين لا يظهر كحفظ ناجح.

## لغة التعبيرات

- `{"kind":"literal","value":10}`: قيمة رقمية أو نصية أو منطقية أو قائمة.
- `{"kind":"input","name":"price"}`: مدخل بالاسم.
- `{"kind":"ref","name":"previous"}`: ناتج بلوك سابق.
- `{"kind":"op","op":"mul","args":[…]}`: عملية من القائمة المغلقة.
- `{"kind":"if","test":…, "yes":…, "no":…}`: شرط منطقي؛ يُنفّذ الفرع المختار فقط.
- `{"kind":"map","list":…, "body":…}`: تكرار على قائمة، و`{"kind":"item"}` داخل الجسم يقرأ العنصر الحالي. الخرائط المتداخلة لها نطاق عنصر مستقل.

### العمليات

| عدد المدخلات | العمليات |
|---|---|
| اثنان | `add`, `sub`, `mul`, `div`, `gt`, `eq`, `and`, `or`, `split`, `join` |
| واحد | `round`, `not`, `trim`, `upper`, `lower`, `length`, `sum`, `sort`, `unique` |

الحسابات تقبل أرقاماً فقط من دون تحويل نصي ضمني. `div` ترفض الصفر. `round` تقرّب لمنزلتين عشريتين باستخدام أرقام JavaScript وليست حساب أموال عشرياً دقيقاً. `sort` ترتيب عددي. `length` يعد وحدات UTF-16 للنص أو عناصر القائمة؛ ليس عداد graphemes للحروف المرئية. `join` تقبل قائمة نصوص وفاصلاً نصياً، و`split` نصاً وفاصلاً. `eq` تقارن القيم المدعومة بنيوياً بتمثيل JSON. `and` و`or` يفحصان الطرفين؛ الكسل يخص `if` فقط.

### مثال قابل للاستيراد: مضاعفة الأعداد الموجبة فقط ثم جمعها

```json
{
  "version": 1,
  "title": "Double positive values",
  "inputs": [{ "id": "numbers", "label": "Numbers", "type": "list", "default": [1, -2, 3] }],
  "nodes": [
    {
      "id": "doubled",
      "expr": {
        "kind": "map",
        "list": { "kind": "input", "name": "numbers" },
        "body": {
          "kind": "if",
          "test": { "kind": "op", "op": "gt", "args": [{ "kind": "item" }, { "kind": "literal", "value": 0 }] },
          "yes": { "kind": "op", "op": "mul", "args": [{ "kind": "item" }, { "kind": "literal", "value": 2 }] },
          "no": { "kind": "literal", "value": 0 }
        }
      }
    },
    { "id": "total", "expr": { "kind": "op", "op": "sum", "args": [{ "kind": "ref", "name": "doubled" }] } }
  ],
  "outputs": ["doubled", "total"]
}
```

المتوقع: `doubled = [2,0,6]` و`total = 8`. هذا مثال اختبار، لا اعتماد لكل تعريف جديد.

## حدود الأمان

- لا `eval` أو `Function`، ولا JavaScript/Python مولّد يُشغّل من هذا المفسّر.
- لا شبكة ولا قاعدة بيانات ولا ملفات ولا DOM ولا مفاتيح ولا shell ولا تركيب حزم أو نشر أو تعديل الموقع. الاستيراد والتخزين والتصدير أزرار واجهة يطلبها الزائر، وليست قدرات للبرنامج.
- حتى 60 بلوكاً، 400 تعبير، عمق تعبير 16، 12 مدخلاً و12 مخرجاً، وقوائم حتى 100 عنصر، ونص مفرد حتى 4000 محرف، و5000 خطوة للتشغيل.
- القيمة المركّبة محدودة أيضاً إلى 1000 قيمة و16000 محرف إجمالاً وبعمق 4. القيم الرقمية منتهية وفي حدود ±10^12.
- تعريف JSON محدود إلى 60000 وحدة نصية (والملف المستورد إلى 60000 بايت)، والنتائج الإجمالية إلى 32000 وحدة نصية. يتوقف عند الخطأ، بلا نشر نتائج جزئية على أنها ناجحة.
- تغيير JSON يعطّل التشغيل والحفظ والتنزيل حتى تطبيقه، لمنع تشغيل نسخة قديمة مختلفة عما يراه المستخدم.
- الأداة لا تفسر الوحدات تلقائياً ولا تحل محل مسار الفواتير أو الدفع الفعلي.

## تعليم شاهين وفحوصه

المنهج القائم بالفعل يحتوي فهرس لغات ومسارات برمجة؛ أُضيفت دروس عملية لعقد الأداة، تدفق البيانات، الشروط والتكرار، الأنواع، الاختبارات، الأمن، الخوارزميات وهندسة النشر. المسارات التعليمية ليست ادعاء تثبيت كل المفسرات أو إتقان كل العلوم. لم يُدرّب نموذج خارجي ولم تُعدّل أوزانه.

`toolBuilderBench()` يركّب الأمثلة ويفحص نواتجها. مدرسة شاهين تشغّله ضمن تدريبها العملي، والمشرف يعيد فحصه مع تقرير المدرسة. لا تقرير نجاح مختلق ولا تعديل يدوي لتقارير `src/data/live/`، ولا روبوت أو جدولة جديدة.
